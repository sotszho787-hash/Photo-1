# 裝修實景相片後製：忠實原貌 × 無印風 × 真實光線

## 首要規則（最高優先）

把相片視作真實工程交付記錄，而非室內設計概念圖。**照片中的所有原有物件及裝修必須保留，絕對不可增減、移動、替換、重畫或改造。** 包括：牆、門、窗、窗外風景、地板、櫃門數量及縫隙、五金、石紋、木紋、反射、燈具、線條、間隔、雜物、個人物品。不可改變物件顏色至與實物不符；尤其不得把木材紋理「美化」成另一種木料。**即使現場不夠整齊，也不能自行移除雜物**；如使用者另行明確同意物件刪改，應視為不同工作，並先區分不再是本 Skill 的嚴格忠實模式。

禁止：生成或消除物件、Generative Fill、inpainting、天空或窗景替換、擴圖、AI 重建房間、改建材、模擬不存在的直射陽光、增添光斑、投射虛構窗框影子、添加裝飾、重置鏡頭透視。**美感不能凌駕真實性。**

## 預設美術方向

- 風格：MUJI / 無印風的**自然、安靜、通透、低彩度、柔和但有層次**；不是褪色、奶油黃濾鏡或灰白失去質感。
- 色彩：奶白、暖灰、天然木色；牆身白位保持中性至微暖；避免黃牆、橙木、偏綠、偏紫。
- 明暗：可稍微提升曝光與暗位層次，但保留窗框、白櫃、石材的高光細節與陰影深度。
- 材質：木紋、石紋、金屬質地要仍然清晰；不靠虛構紋理及過度銳化製造質感。
- 強度：預設「輕度」；如果處理前後一眼像換了單位，就過度了。

## 工作流程

1. **檢查原相。** 列出房間類型、主要建材顏色、光線來源、是否有**可見窗戶**、窗外是否過曝、室內是否混合日光與黃燈、偏色、噪點與不足。分清「看得見窗」和「推測窗在畫面外」。不確定的光源不可當作已證實。
2. **選擇光線策略。** 依據下方「按窗分流」；詳細判斷參閱 [光線與驗收參考](references/lighting-and-qa.md)。
3. **擬定最少必要調整。** 優先用非生成式、可逆的曝光、白平衡、色調曲線、HSL 與局部明暗工具。不能操作圖像時，輸出明確建議而不要假稱完成。
4. **執行。** 如 Codex 可以讀寫本機照片，建議使用本 Skill 附帶的 `scripts/grade_photo.py` 作安全、保留像素位置的初稿；必要時讓使用者在 Lightroom、Photoshop、Camera Raw 進一步微調。禁止未經要求覆寫原檔。
5. **質檢。** 以 100% 比較原圖及後製圖：相同解像度、構圖、物品數量、櫃門分割、木紋走勢、磁磚與石紋、窗景、反射均未改；色彩合理，窗外無嚴重死白、室內無不自然光圈或異常黃灰。
6. **交付。** 保留原圖，輸出新檔，附一句簡短調整紀錄：`光線類型｜曝光/色溫/暗位/高光｜有否加入柔和窗光｜忠實性限制`。無法確定之處請坦白說明。

## 按窗分流：光線為重點

**A. 畫面有真實窗戶，且能判斷方向**
- 優先降低窗外過曝、拉回高光，讓室內暗位漸進抬升（避免「窗外死白、室內死黑」）。
- 可依**實際窗戶位置**極輕微增加柔和、擴散的環境光感；維持原有光影走向與材質，不創造新光斑、硬影或窗格陰影。
- 若窗外內容已經完全白掉、沒有資料，**不可生成虛構窗外風景**；如實保留其限制。

**B. 未見窗戶，但有可靠的窗外來光證據**
- 可利用既有光線方向微調局部亮度；如果無法判斷來源則轉到 C。不能在相片中加入不存在的窗、光束或新陰影。

**C. 無窗戶 / 光源不明確**
- 以現有室內照明為基礎平衡偏色、提升暗位、減弱刺眼亮燈；維持合理房間明暗，不假裝有日照。
- 仍然可做到 MUJI 風，但靠色彩、對比和空間層次，不靠假陽光。

**D. 混合光（窗光 + 黃燈 / LED）**
- 控制色溫分離：白牆不發黃、不發青，燈具仍保留原有光感；避免全局白平衡改到燈光或天然木色失真。需要時以實際光源區域作保守局部調整。

## 可直接執行的安全初稿

本 Skill 內的 `scripts/grade_photo.py` 只做逐像素色調與光線運算：**不使用生成模型、不重畫內容、不移動物件**。它不是自動識別窗戶的 AI；請先視覺判斷光源，再指定參數。需安裝 Python 3、`Pillow`、`numpy`：

```bash
python -m pip install Pillow numpy
python scripts/grade_photo.py "input.jpg" "output.png" --light window --window-side left --strength 0.55
```

- `--light window`：已確認窗戶；`--window-side left|right|top|bottom` 只在看到真正光源方位時使用，否則 `none`。
- `--light no-window`：沒有窗 / 只有人工照明，不加窗光方向性調整。
- `--light unknown`：不知道光源，做最保守的中性色調初稿（預設）。
- `--strength 0.35`：極輕度；`0.55`：標準輕度；`0.8`：較明顯。請先比較，不要無理由調到 1。
- 輸出除了最終檔，另外寫出 `*_compare.jpg` 原圖/後製拼圖與 `*_report.json` 記錄。請勿把比較圖當最終宣傳圖。
- 如用其他照片編輯工具，**仍需遵守前述保真規則**。不具備圖片存取、編輯工具或執行權限時，不能聲稱已完成修圖。

## 使用者額外要求的邊界

「加自然光」不等於在室內畫上陽光；先看有沒有真實窗光依據，*有才輕微加強原有的漫射光*。如無真實依據，以自然的白平衡和曝光達到明亮感，不捏造光源。若任務衝突，例如同時說「一件東西都不能改」與「把桌上雜物刪掉」，先維持物件完整，清楚指出需另行授權的變更。

## 交付回覆格式

簡短寫：

`光線判斷：...｜調整：...｜自然光：有/無及理由｜保真檢查：...` 

如有處理檔案，再附後製圖與原圖對照；不要只給一段假設已執行的修圖描述。

## Windows 一鍵批量後製擴充（Batch v2，Codex 可執行）

當用戶要求「A：一鍵批量後製」時，優先使用本套件根目錄的 `RUN_BATCH.bat` 或 `python -m app.batch`，**不是需要持續運行的監察程式**。每次獨立讀取 `workspace/INPUT` 或一個 ZIP／照片資料夾，產生兩種同尺寸非生成式色彩版本（Faithful 忠實、Aesthetic 光亮唯美）、各自的 Before/After、個別 QA JSON、批次 CSV/JSON 及交付 ZIP。輸入絕不覆寫。

**Batch 執行方法：** 先在套件根目錄執行 `install_windows.bat`，然後執行 `RUN_BATCH.bat`；也可在 Codex 終端於套件根目錄使用 `.venv\Scripts\python.exe -m app.batch --input "C:\your\photos.zip"`。套件的實際根路徑記錄在安裝後的 `BATCH_PACKAGE_LOCATION.md`。Codex 必須先確認本機執行權限、檔案可達，不能假設雲端 Codex 直接看見 Windows 本機檔案。

**光線真實性：** 程式沒有視覺語義的窗戶辨識能力；預設 `unknown`，只做保守的全局微調。只有在 `lighting_overrides.csv` 人工核對真實窗戶方位後，才允許非常輕微的既有漫射光過渡。亮度最高的畫面邊緣不是窗戶證據。兩個版本都不能加假陽光、移除雜物、改傢俬、改木紋。

**避免 4 MiB 訊息錯誤：** 不把圖片 base64 或完整大型 log 送回 Codex/ChatGPT 對話；工具只在本機讀寫檔案，回覆成功/失敗數、QA 結果摘要及成品 ZIP 路徑。完整檔案留在磁碟。每次輸出一個 ZIP，不等於要將 ZIP 二進位夾在工具訊息內。
